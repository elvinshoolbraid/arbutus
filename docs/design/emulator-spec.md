# Emulator Spec — Arbutus desktop

What the MacBook build is, how it's driven, how it's verified. Created 2026-09-08.

---

## 1. Purpose

Run ArbutusOS on a MacBook with the real 320×240 framebuffer, so the demo is the actual UI and audio, not a mock. Hardware parity via identical driver interfaces (`DisplayDriver.update(pixels)`, `InputDriver` callbacks, `AudioDriver` callback) — unchanged from current `emulator/drivers/*.py`.

*As built (2026-10-13, #633, finding m-emu-ui-drivers #7):* the live input seam is two
callbacks, `on_control(name, pressed)` (a key by its control name) and
`on_encoder_turn(encoder, delta)`. The test harness's `ScriptedInput` and the device's
`UartInput` each set them; the `InputDriver` base class still declares six older callbacks
nobody sets and not `on_control`. The desktop window uses no input driver at all:
`emulator/main.py` calls the app's `on_key` directly. Audio is made by the `arbutus-audio`
process (§ 4), not by an `AudioDriver` in Python.

## 2. Window

- Backdrop: `docs/design/reference/lookalike-model.jpg` scaled to fit the display. Elvin paints an alpha hole where the LCD is; the framebuffer is blitted through it at the largest integer scale that fits the hole.
- Hotkey (`Z`) toggles a zoomed framebuffer pane (3× or 4×, integer) for reading the screen.
  *As built (2026-10-13, #633, finding m-emu-ui-drivers #2):* the pane is the largest integer
  scale up to 3× that fits, counted in the window's device pixels, so on a Retina screen it is
  1.5× the LCD's size and after `M` smaller than the LCD; never 4×.
- Pressed keys draw a thin outline on the photo for ≥ 1 frame (visible in screenshots).
- No encoder rotation indicator.

## 3. Input mapping

| Physical | Emulator |
|---|---|
| command keys, page keys, 1–4, ‹ ›, A–Z, transport, LIFT/DROP/SLICE, TEMPO, HELP | mouse click on photo hotspot |
| SHIFT | physical MacBook Shift (so SHIFT + mouse-click combos work) — hotspot also clickable |
| HELP hold | mouse-down on HELP hotspot held |
| chromatic keys | MIDI note in (velocity honoured), **or** internal input mode (below), **or** a mouse click on the note's hotspot (`NOTE_0`…`NOTE_23`; 2026-10-13, #633: "not mouse" was never built, finding m-emu-ui-drivers #10) |
| encoders | MIDI CC, relative mode (delta); click-and-drag up/down on an encoder hotspot; mouse wheel over one |

**Internal input mode** (added 2026-09-09; the MIDI keyboard's USB port is broken).
Chromatic keys are piano-aligned on the Mac's top two letter rows — `a s d f g h j k l ;`
= whites F..A, `w e r · y u · o p` = the blacks above the pairs they split. 17 keys;
`‹ ›` shift octave for the rest. Encoders respond to click-and-drag, `ENC_DRAG_PX`
(6) pixels per step. Both paths stay live alongside MIDI.

- Hotspots: `emulator/chrome/keymap.json`, name → polygon in photo pixel coords. Generated by `tools/calibrate_keymap.py` (`--only KEY` to redo one).
- MIDI config: `emulator/midi.toml` — device name substring, CC numbers for ENC1–4, relative encoding style.

**macOS:** SDL audio must stay off — `pygame.init()` deadlocks against the CoreAudio
stream sounddevice owns. `main.py` uses `pygame.display.init()` and `SDL_AUDIODRIVER=dummy`.
The LCD cutout only fits a 1× framebuffer above ~1800 px window width; use `--width 1800`.

## 4. Audio

~~48 kHz, stereo, float32, 256-sample buffer via sounddevice. Synth 8 voices, drum 24 one-shots, summed → mixer → master → out. Tape: 4 stereo tracks × 2 min in RAM (CM4 bandwidth is a later problem).~~

*Superseded (2026-10-13, #633, finding m-emu-app #12; the build changed at stage N1, 2026-09-17,
and #297):* there is no Python audio. Every sample is made by the `arbutus-audio` process in
`audio/`, the same one the device runs (`emulator/notes/audio-host.md`); its process model,
rack and protocol are `engine-spec.md` § 5–8. The tape has **8** stereo tracks
(`emulator/app/tape.py` `NUM_TRACKS`), streamed to and from storage, not held in RAM:
`tape-streaming-design.md`. The UI keeps only the clip geometry.

## 5. Persistence

`emulator/state/` — autosaved slots, project, and the tape: `tape.json` (clip geometry)
plus `tape-N.wav` per track, written out of the audio process. Survives restart.
`--fresh` wipes.

*2026-10-13, #633:* the as-built is `emulator/notes/state-and-files.md` § Persistence (the
files, what writes each and when). Since #297 the audio process writes a track's medium (the
file its audio is stored in) during the take, into the open project's folder; since #817
(Play date 1, D97) a project is always open, so the media live in it.

## 6. Library

The library is **`audio/library/`** — it is content the audio process loads (`engine-spec.md`
§7), not the UI's, and since stage N1 there is no second copy under `emulator/`.

```
audio/library/
  synth/<box>/<patches or wavs>
  drum/drum/<kit folders: wavs + kit.json>
  fx/racks/<rack files>
  seq/endless/<pattern files>
```
Folders discovered at boot = menu contents; the folder name under a category **is** the box
name (`synth/osc/` is `arbutus/osc`), so there is no index to keep in sync. Elvin supplies
WAVs.

## 7. Verification harness

Generated by `/create-verification-skill` into the agent tooling (private).

- **Seam:** scripted `InputDriver` (feeds key/encoder/MIDI events from a script) + headless `DisplayDriver` (captures `pixels` to PNG) + null `AudioDriver` (captures buffers to WAV). No pygame needed in CI.
- **Drive:** feature scripts in `verify-arbutus/features/*.md`, each = event list + expected end state.
- **Evidence:** PNG per screen state under `validation/ui/<feature>/<state>.png`; WAV for audio checks.
- **Grade:**
  1. baseline PNG exists → pixel diff must be 0;
  2. else → Opus subagent reads PNG + `ui-aesthetic.md` §5 checklist + relevant sketch, returns pass/fail with notes; on pass, PNG becomes the baseline after Elvin approves.
- North-star trace: `tape-sampling-workflow.md` §5.1.
